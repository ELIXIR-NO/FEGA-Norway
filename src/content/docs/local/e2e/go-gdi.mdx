`e2e-gdi` is a deliberate placeholder that exits non-zero, so a GDI run can never be read as a
pass.

<Steps>

1. **Select the distribution**

   ```bash
   E2E_ENV=gdi ./dev.sh start
   ```

2. **Expect failure**

   The binary prints `e2e-gdi: the GDI pipeline is not implemented` to stderr and exits 1.

</Steps>

<details>
<summary>why does it fail on purpose?</summary>

Nothing about a GDI run should be readable as a pass while no GDI pipeline exists. Exiting
non-zero with an explicit message means a scheduled or scripted run surfaces the gap instead of
hiding it.

</details>

<details>
<summary>how is the distribution selected?</summary>

`E2E_ENV` picks which binary the runner's entrypoint executes, and each binary fixes its own
pipeline. Nothing selects an environment at runtime: choosing the environment is choosing the
program.

</details>
